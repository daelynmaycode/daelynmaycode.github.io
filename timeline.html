05 / 07 Development Timeline

Eleven days that turned a ROM into a world.

This record covers the working history of the project from the first verified build to the current tree. Every entry corresponds to a document, a package or a passing suite in the repository — not to a plan.

11 – 22 November 2026 Reverse chronological source

22 November 2026

Input repaired, rules typed, capital rebuilt, heroes pipelined

The largest single day. The Settings screen was crashing on a nil slider because every look control had never been registered; the title suite failed 17 checks and controls failed 5. All three now exit clean. A duplicated Cancel binding was removed in favour of context ownership, and the underwater rise acceleration was retuned from 9.0 to 30.0 m/s².

On the same day the typed battle-rules layer shipped (54 checks over all 1,024 table entries), Coneria was torn out and rebuilt from its own town map, and the MetaHuman intake pipeline plus its Ghibli shading pass landed. By the end of that day four exported MetaHuman hero bodies held the slot, and a pass over the mixed asset drop put real books, wine bottles, cargo crates, shovels, shelves and inn beds into the interiors.

21 November 2026

The quality gate, and a route to something playable

An asset quality audit and a playability completion tracker were written, and the first honest conclusion was recorded: the slice is a systems demonstration, not a game. That produced the S0–S7 route — input ownership, battle rules, encounter bridge, progression, dungeon kit, Pravoka, and a single end-to-end acceptance run.

A milestone definition was also tightened: a stage is only complete when its packaged deliverable exists.

16 November 2026

Vertical slice recorded; interface polished

The M4/M5 feature and limitation record was finished, alongside a character production guide. The pause menu was cut to exactly five choices, the Satchel was moved behind its own key, the Field Menu was limited to plain section names, and the world stamina gauge became a compact continuous ring.

15 November 2026

Environment and rendering contracts written

The shared day/night, weather and water architecture was documented as one state object with a director, rather than per-system implementations. The rendering pipeline document fixed the feature contract, the quality tiers and what the "Nanite-inspired" claim does and does not mean.

13–14 November 2026

Data extraction becomes the spine of the project

The overworld, tile properties, walkability and a BFS route from the start position were decoded. Then the battle tables: 128 enemies, 44 AI records, 128 formations, 128 encounter domains, the formation-weight selector and the map encounter rates — all validated at 117 checks against the ROM.

In parallel, the first Poly Haven PBR library was mapped onto the blockout architecture, and bridge geometry was iterated through a dozen verification views.

12 November 2026

The world layout is approved and locked

A 4,000 × 4,000 m footprint at 15.625 metres per reference tile was approved, replacing an earlier 16,384 m proposal. Eight settlement footprints, the Coneria castle curtain, six regions, sixteen landmark footprints and the coordinate convention were written into canonical JSON with a runtime validator.

11 November 2026

Milestone 1: a byte-identical Final Fantasy

Disch's documented v1.0 disassembly was reassembled with the bundled assembler and linker, then compared against the original cartridge. Result: 262,160 bytes, SHA-256 D360BEEE…549667, zero differing bytes. Automated Lua input drove the rebuilt ROM through intro, party creation, naming, overworld movement, a random encounter, victory and the return to the overworld in FCEUX.

The same day the Godot project opened: a third-person controller, spring camera, collision, a deterministic overworld, Coneria with gate, walls and fountain, one enterable house, one NPC and a packaged Windows build.

05.1 Decisions

Six choices that shaped the build.

These are recorded in the project's implementation log because each one closed off an alternative that would have been easier in the short term.

Battle staging

A dedicated arena, not combat in place

Encounters will resolve in a reusable staged scene — party left, enemies right, lit from the region's palette and weather — instead of fighting where the encounter triggered. It keeps Active Time Battle pause semantics and camera framing stable, and avoids inheriting slope, collision and streaming fragility.

Input

One Cancel, owned by context

Skip-cinematic shipped with no default binding. Because a gameplay cinematic owns Cancel while it runs, the pause menu refuses input whenever a cinematic is active. A migration strips the old duplicate binding from saved profiles.

Data

JSON is the authority; code only reads it

Extracted tables live in JSON and are loaded once into a read-only typed layer. No caller indexes a raw array. Loading is strict: a bad count, a non-contiguous id or a broken cross-reference makes the layer refuse to become ready, so combat cannot run on tainted tables.

Art

Blockout geometry, real materials

Rather than wait for final meshes, the project paired placeholder geometry with a genuine PBR surface library. It proves lighting, scale and material response early, and makes the remaining work a replacement job rather than a research problem.

Characters

A MetaHuman slot with a clean fallback

Heroes are defined in data, not assembled in code. A MetaHuman body is attempted first and silently rejected if its skeleton fails the Humanoid contract, falling back to the authored body — so an unfinished character can never block the build. Four exported bodies — Fighter male and female, Thief, Monk — now sit in that slot.

Process

Verified means measured

Every claim in the implementation log carries a suite result and an exit status. Where a check fails — the swim-up assertion, the missing castle reference plan — it is written down instead of being quietly dropped from the report.

The project

An independent, from-scratch 3D remake of Final Fantasy I, built in Godot 4.7 and documented in the open. Progress on this site is updated from measured build results, not intentions.
