06 / 07 Development Roadmap

Eighteen milestones left, and one that matters most.

The project runs on numbered milestones, each closing only when a packaged deliverable exists. Five are signed off in whole or in part; the rest are scheduled. The critical path runs through battle: until encounters resolve, none of the world's content is actually playable.

06.1 Milestones

The ledger.

Status is a property of the deliverable, not of the effort. A milestone with unfinished art stays open even when every system in it runs.

M1 NES reconstruction Byte-identical rebuild, verified in an emulator, packaged. Complete
M2 Original data extraction Overworld, tiles, enemies, AI, formations and domains decoded. Items, spells, classes, maps and dialogue remain. 4 of 9 done
M3 Technical architecture Build and overworld format documented; schema package, gameplay core API and combat-math tests outstanding. In progress

M9–M11 Characters & combat Modelled classes and animations, the turn-based battle scene, targeting, damage, status, spells, enemy models and bosses. Planned
M12–M15 Systems & content Classes and promotion, XP and levels, equipment, inventory, shops, economy, treasure, magic effects, dungeons, quests and story progression. Planned
M16–M20 Presentation & release Original audio, menus and UI art, save/load, content completion, optimisation, testing and a final downloadable build. Planned

What is actually finished.

Complete

  • Duplicate Cancel binding removed; cinematics own Cancel while active
  • Underwater rise retuned to 30 m/s² so a jump reverses a dive in 0.2 s

Complete
  • Read-only typed layer over 128 enemies, 44 AI records, 128 formations and 128 domains
  • Strict load: counts, id contiguity, raw sizes and every cross-reference validated
  • Variant-B count selection, weight probabilities and map encounter rates decoded once
  • 54-check suite pins every field of all 1,024 table entries

Complete

06.4 Upcoming

The route to a first acceptance run.

Seven stages between the current build and a fresh save that can walk out of Coneria, fight, level, enter the Chaos Shrine and take a ship. No dates — sequence only.

S2 — Active ATB, battle UI, enemies, resolution

Not started

The dedicated arena, ATB gauges, command entry, enemy turns, damage and status resolution — driven entirely by the typed rules layer.

S3 — Field encounter bridge

Not started

Encounter domains and rates select formations; the field hands the party and the formation to the arena; the result returns to the field.

S4 — XP, levels, charges, loot, persistence

Not started

Progression finally becomes real: experience, level-up growth, spell charges, dropped loot and a save that carries all of it.

S5 — Dungeon kit, Chaos Shrine, Garland

Not started

A reusable dungeon kit, the first real interior, and the Garland encounter that currently exists only as a placed model.

S6 — Pravoka, pirates, ship

Not started

S7 — Fresh New Game to ship acceptance run

Not started

One unbroken run from a new save to the ship, with no debug travel and no console commands. This is the moment the project becomes a game.

06.5 Long term

What "finished" would mean.

The end state is a complete remake, not a demo — but it is defined so it can be recognised when it arrives.

A complete world

Eight settlements at production quality, sixteen landmark surfaces with real interiors, and authored countryside across all six regions.

The original rules, exactly

Turn-based combat driven by the decoded tables: formations, morale, elemental weakness, AI scripts and encounter rates identical to the ROM.

The whole party

All six classes with promotion, modelled and animated, with equipment that is visible and class restrictions that hold.

Its own audio

An original soundtrack and sound design replacing the reference material, mixed across the seven existing buses.

A finished interface

The authored UI art pass, with the accessibility and remapping work that already exists retained.

Nothing borrowed

No NES ROM, no original art, no reference soundtrack. The verification project stays separate and unshipped.

Principle

Engine-independent logic

Gameplay rules are testable without rendering. Rendering, UI and audio consume state; they never own it.

Principle

Data over hard-coding

Original data is extracted, documented and validated against the ROM rather than transcribed by hand.

Principle

Two projects, one source

The NES reconstruction stays independently buildable and is never redistributed with the remake.

The project

An independent, from-scratch 3D remake of Final Fantasy I, built in Godot 4.7 and documented in the open. Progress on this site is updated from measured build results, not intentions.
